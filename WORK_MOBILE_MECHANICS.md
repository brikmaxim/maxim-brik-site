# Work / Mobile Mechanics — source of truth

Этот файл — обязательная спецификация для всех правок вкладки `Work`, особенно мобильной версии.

## Главный принцип

Мобильный `Work` не должен быть свободным хаотичным скроллом. По референсу `https://www.goldenhum.com/` это fixed fullscreen state-machine: document почти не скроллится, wheel/touch переключает состояние, а hero-карточки двигаются внутри fixed-сцены.

Поведение должно ощущаться как у `https://www.goldenhum.com/`:

- один жест = один понятный переход внутри fixed-сцены;
- переходы плавные, без фризов, чёрных кадров, прыжков и резких подмен;
- заглавные карточки проектов ведут себя как fullscreen-слайды;
- меню и инфо-плашки остаются частью нашей сетки и стилистики.

## Состояния мобильного Work

### 1. Work menu state

Пользователь видит:

- первую колонку с именем / описанием;
- вторую колонку `Work / About / Team / Message` и `Projects(Selected)`;
- третья колонка ещё не закреплена сверху;
- на фоне сразу видна заглавная R&D-картинка / видео fullscreen.

Важно:

- при входе в `Work` нельзя сразу попадать в состояние R&D с третьей колонкой сверху;
- фон R&D не должен прыгать из середины экрана в fullscreen;
- нижняя карточка NDSP не должна появляться снизу во время первого перехода.

### 2. Menu → R&D state

Первый свайп/scroll из главного Work menu:

- плавно смещает страницу вниз;
- третья колонка прилипает к верхней грани;
- активный проект остаётся `R&D`;
- R&D-фон/картинка не должна менять ориентацию или “пересобираться”;
- не должно быть видно нижней части второго столбика сверху;
- не должно быть видно NDSP снизу.

Это именно плавное смещение страницы, а не slide между проектами.

### 3. Project slider state

После того как R&D уже в состоянии с третьей колонкой сверху:

- следующий свайп вниз переключает `R&D → NDSP`;
- следующий свайп вниз переключает `NDSP → ANGEL333`;
- свайп вверх переключает обратно;
- один свайп не должен перескакивать через проект;
- нельзя зависать между двумя проектами;
- нельзя показывать две заглавные картинки пополам.

Это fixed fullscreen vertical slider: карточки стоят слоями `-100vh / 0 / +100vh` и двигаются через один transform.

Desktop и mobile должны использовать одну и ту же механику project slider:

- один active project;
- каждый hero — fullscreen fixed-layer;
- соседние проекты находятся на `-100vh / +100vh`;
- wheel/touch меняет project index;
- JS управляет только индексом и transform, без blur-подмен.

## Back / Up

Когда пользователь провалился внутрь проекта через заглавную карточку:

- нижняя кнопка должна быть `Back`;
- `Back` возвращает туда, откуда пользователь провалился;
- в открытом проекте нельзя тяжелым свайпом вверх вернуться к первым двум колонкам меню.

Когда пользователь не внутри проекта:

- `Up` возвращает к главному Work menu.

## Заглавные карточки

Общие правила:

- карточка должна занимать весь экран;
- не должно быть белых/чёрных полос по краям;
- R&D и NDSP должны двигаться одинаковой механикой в project slider state;
- отдельный R&D background можно использовать только для Work menu state, но не для project slider state;
- никаких случайных rotate-анимаций при переходах;
- orientation override допустим только как статичная настройка конкретного медиа.

## Верхний gradient blur

- показывается только на вкладке `Work`;
- не показывается на `About`, `Team`, `Message`;
- высота — увеличенная, примерно в 2 раза от старой версии;
- находится между фоновой картинкой и плашками меню.

## Плашки

- плашки в тёмной теме полупрозрачные;
- фон за плашками должен размываться;
- текстовые отступы должны быть одинаковыми;
- third/details column должна оставаться поверх заглавной картинки.

## Запрещено

Не делать:

- смешивать native CSS scroll-snap с fixed-stage механикой;
- делать project switching через простую blur-подмену без движения;
- показывать соседний проект во время первого перехода menu → R&D;
- скрывать первые две колонки вместо правильного смещения scroll-позиции;
- добавлять случайные rotate/scale-анимации на R&D;
- менять desktop layout, если запрос касается только mobile;
- править механику “на глаз” без сверки с этим файлом.

## После каждой правки

Обязательно:

1. Обновить cache-bust в `index.html`.
2. Проверить `portfolio.js` через `node --check`, если менялся JS.
3. Убедиться, что правка не возвращает:
   - свободный scroll;
   - split-screen между двумя проектами;
   - NDSP снизу в переходе menu → R&D;
   - прыжок R&D-фона при входе в Work.
